# PS024 — CMD_VAR_EXPANSION

**Severity** `warn` · **Confidence** `high` · **Affected targets** `posix-sh`, `powershell`

`%VAR%` expansion is cmd.exe-specific and stays literal in non-cmd shells.

## Why it breaks

- cmd.exe expands %VAR%. ([source](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/set_1))
- PowerShell reads environment variables through $Env:NAME rather than cmd.exe %NAME% syntax. ([source](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_environment_variables))
- POSIX sh treats % as a literal character. ([source](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/V3_chap02.html))

## Bad examples

- `echo %APPDATA%`
- `mkdir "%USERPROFILE%\build"`

## Good examples

- `echo $HOME`
- `node -e "console.log(process.env.USERPROFILE)"`

## False positives

Format strings without a closing percent (printf "%s\n", date +%Y) never match. cmd-style FOR variables (%%i) are out of scope for v0.1.

## Fix (manual)

Manual: explained only — never applied automatically.
