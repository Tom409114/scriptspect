# PS013 — POSIX_MKDIR_P

**Severity** `error` · **Confidence** `high` · **Affected targets** `cmd`

`mkdir -p` semantics (create parents, ignore existing) do not carry over to cmd.exe.

## Why it breaks

- POSIX -p creates missing parents and does not error when the directory exists. ([source](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/mkdir.html))
- cmd.exe mkdir errors when the directory already exists and has no -p flag. ([source](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/mkdir))

## Bad examples

- `mkdir -p dist/assets`
- `mkdir -p a/b/c`

## Good examples

- `shx mkdir -p dist/assets`
- `node -e "require('fs').mkdirSync('a/b/c',{recursive:true})"`

## False positives

Plain `mkdir` (no -p/--parents) is not reported: cmd.exe has mkdir and `mkdir a\b` creates parents. Only the flag form differs.

## Fix (conditional)

Conditional: applied only when the required dependency is already installed; otherwise surfaced as a plan. `--fix` never installs dependencies.
