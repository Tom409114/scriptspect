# PS001 — POSIX_INLINE_ENV

**Severity** `error` · **Confidence** `high` · **Affected targets** `cmd`, `powershell`

Inline environment assignments (`FOO=bar cmd`) require POSIX sh semantics.

## Why it breaks

- Assignment prefixes are a POSIX shell feature that applies env vars to one command. ([source](https://www.gnu.org/software/bash/manual/html_node/Environment.html))
- PowerShell assigns environment variables through the Env: provider, not POSIX assignment prefixes. ([source](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_environment_variables))
- cmd.exe has no per-command assignment; `set` persists in the session and `FOO=bar cmd` would try to run a program literally named FOO=bar. ([source](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/set_1))

## Bad examples

- `NODE_ENV=production vite build`
- `A=1 B=2 node app.js`
- `GIT_AUTHOR_NAME=x npm publish`

## Good examples

- `cross-env NODE_ENV=production vite build`
- `node app.js`
- `vite build`

## False positives

Not reported when the command is already cross-env/cross-env-shell (the portability layer exists), or inside explicit shell wrappers.

## Fix (conditional)

Conditional: applied only when the required dependency is already installed; otherwise surfaced as a plan. `--fix` never installs dependencies.
