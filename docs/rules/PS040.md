# PS040 — MISSING_LOCAL_BIN

**Severity** `warn` · **Confidence** `high` · **Affected targets** `posix-sh`, `cmd`, `powershell`

Script uses a local CLI tool that is not declared in dependencies or workspace bins.

## Why it breaks

- npm run-script walks from the script cwd to the filesystem root and adds each ancestor node_modules/.bin to PATH. ([source](https://github.com/npm/run-script/blob/main/lib/set-path.js))
- pnpm run explicitly adds the workspace-root node_modules/.bin to every workspace package script PATH. ([source](https://pnpm.io/cli/run))
- Yarn Classic hoists compatible workspace dependencies to the root node_modules tree, while version-mismatched dependencies come from the registry. ([source](https://classic.yarnpkg.com/lang/en/docs/workspaces/))
- Yarn PnP keeps a root binary root-only; each workspace using the binary must declare its provider. ([source](https://yarnpkg.com/features/pnp#shared-binaries))
- New Bun workspaces default to isolated installs, where packages are expected to access only explicitly declared dependencies. ([source](https://bun.sh/docs/pm/isolated-installs))

## Bad examples

- `vite build  (vite not in dependencies)`
- `jest  (jest not installed)`

## Good examples

- `vite build  (vite in devDependencies)`
- `my-workspace-tool  (workspace bin)`

## False positives

Only commands in the known-tool registry are checked — arbitrary words are never flagged. Dependency aliases are resolved to their provider, workspace packages must expose a real bin through a compatible dependency, and root toolchains count only for deterministically identified npm/pnpm or non-PnP Yarn Classic workspaces.

## Fix (conditional)

Conditional: applied only when the required dependency is already installed; otherwise surfaced as a plan. `--fix` never installs dependencies.
