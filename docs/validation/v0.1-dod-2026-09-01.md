## 仓库内已关闭的主要缺陷簇

1. **Parser 与 rule truth**：POSIX sh、cmd 与 opt-in PowerShell 使用独立 target parses；quote、escape、operator、redirection、expansion、wrapper payload 与 PS050/PS051 均有结构化证据和 span。
2. **输入与边界**：root/config/workspace manifest 使用 canonical containment；严格 UTF-8/JSON、duplicate root/scripts keys、非字符串 scripts、unknown config fields/targets/rules 被拒绝。
3. **Schema 与包内容**：`schema/config.schema.json`、`schema/output.schema.json` 为生成契约，包清单包含 schemas、双语 README 和 bundled Action。
4. **Fixer 安全**：只重写根 `scripts`；依赖门基于真实声明；多文件写使用 crash-stable transaction、race/hardlink/inode 检查、重新分析、rollback 与显式 manual recovery。
5. **First-class Action**：`action.yml` 指向 Node 24 bundle；不运行 shell/npm/network；严格校验 inputs，先写 annotations/summary/outputs 再失败，默认只读。
6. **CI 与 release code**：PR jobs 最小权限、frozen lock、真实 Action/package consumers 与 coverage/benchmark gates；无环境权限的 intent discovery 先让普通 main CI 安全短路，只有精确 release-please intent 才申请发布审批。coordinator 持久化唯一候选和四个预最终资产，再以 exact tag 显式 dispatch OIDC publisher。发布器按评审过的 exact/canonical 完整性模式验证真实 registry bytes，用 executable-source digest 绑定 comparator，以有界退避处理传播；`alias-planned`/`final-planned`、全局 publisher lock、per-SHA state lock、Latest 单调判断和精确 CAS rollback 关闭并发、重试与崩溃窗口。
7. **首页与证据**：PR #78 交付响应式品牌 hero、中英双版切换、真实 before/result/patch/after、托管 Action annotation/summary 证据与发布状态渲染；单一 fixture 防止 demo 漂移，pre-release 状态不展示不存在的 npm/Action 命令，comparison 不自动宣布胜负。
8. **安全跟进**：Private vulnerability reporting 已启用；PR #79 修复 scoped package purl 的不完整编码，准确 main CodeQL job success，当前 `refs/heads/main` 没有 open CodeQL alerts。
